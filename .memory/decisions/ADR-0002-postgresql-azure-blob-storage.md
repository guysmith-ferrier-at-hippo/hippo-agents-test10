# ADR-0002: Adopt PostgreSQL and Azure Blob Storage for Persistence

## Context
The service must store structured transactional data (licensing applications, applicant profiles, fee reconciliation records, audit logs) and binary file uploads (photographic identification, certificates, supporting proofs). 

Data protection standards require encryption at rest and in transit, strict auditability, and UK data sovereignty.

## Decision
We will use:
1. **PostgreSQL (Azure Database for PostgreSQL Flexible Server):** For all structured relational domain data, transactional workflows, and immutable audit logs.
2. **Azure Blob Storage (with Private Endpoints):** For all binary document uploads and evidence files, encrypted with customer-managed keys (SSE) and accessed exclusively through short-lived Shared Access Signatures (SAS) generated by the API.

## Consequences

### Positive
- PostgreSQL provides robust ACID compliance, JSONB flexibility for dynamic form field schemas, and strong UK government adoption.
- Azure Blob Storage provides cost-effective, durable storage with built-in lifecycle management and virus scanning integration.
- Document binary payloads are separated from relational tables, keeping database backups compact and queries performant.

### Negative
- Application must manage two persistence mechanisms and coordinate orphan cleanup if an evidence upload transaction fails.

## Options Considered
1. **Azure SQL / SQL Server:** Robust relational database, but higher licensing overhead and less flexible JSONB querying compared to PostgreSQL Flexible Server.
2. **MongoDB / DocumentDB:** Good document capabilities, but weaker multi-table relational integrity and constraint enforcement for financial and licensing workflows.
3. **PostgreSQL + Azure Blob Storage:** Selected as the optimal combination for structured transactional rigor and scalable document persistence.
